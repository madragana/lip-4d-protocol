# Security policy

LIP-4D is experimental. Do not use unreviewed examples or preliminary code to protect production systems.

For suspected vulnerabilities, use GitHub's private vulnerability reporting for this repository if enabled; otherwise contact the repository maintainer privately using an established contact channel before public disclosure. Never post credentials, private keys or exploit details in public issues.

Security-critical requirements include trusted workload authentication, fail-closed evidence evaluation, signature algorithm restrictions, audience and digest binding, nonce/replay protection, expiry handling and protected-resource enforcement. See the current Internet-Draft for normative requirements.
